# Backend steering

## Approved guidance

- **Explain each API endpoint briefly.** Include one plain-language sentence
  describing what the endpoint does. Put it in the handler's docstring so it
  appears in both the code and generated API docs. Mention scope or ordering
  when needed to understand the behavior; avoid implementation narration.

## Maintaining this file

Keep only current approved backend principles. Replace or remove changed rules;
do not append endpoint inventories, PR status, or review chronology. Add a rule
only when explicit reusable guidance is needed beyond code/API documentation.
See [the retention policy](README.md).
